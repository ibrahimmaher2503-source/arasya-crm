## السياق والقيود المؤكدة

`Laravel` واستخدام قاعدة علائقية مؤكدان. `modular monolith` هو الاتجاه المقترح، وليس قراراً مقبولاً. لم يُحسم إصدار `Laravel` أو `PHP` أو المحرك/إصداره أو تمثيل المفاتيح أو سياسة migrations. يجب أن يملك كل module كتابات مجاله، وأن تمر التغييرات المالية والمخزنية بمعاملات `idempotent` وقيود قاعدة البيانات وتدقيق/`outbox` وفق [تصميم الحل](../SOLUTION_ARCHITECTURE.md) و[عقود المالية والمخزون](../finance-stock-contracts.md).

يلزم الحفاظ على scope `entity_id` بوصفه `LegalEntity` لا `tenant_id` لـSaaS، وعلى التكامل المرجعي والـdecimal money من [نموذج البيانات](../DATA_MODEL.md). المرجع الملزم هو [PRD](../../product/PRD.md): `ARCH-01/03/04/05/06`, `NFR-02/03/04`. تحديد المحرك لا يحسم سياسات العمل المفتوحة مثل دقة وتقريب الأموال أو تقييم المخزون؛ تلك تبقى لدى مالكيها في `OPEN-03/04`.

نطاق هذه المراجعة هو مقارنة الاختيارات وتحديد دليل القرار فقط. لا تتضمن تصميم schema إنتاجي، أو كتابة/تشغيل SQL أو migrations، أو تثبيت database/tools، أو إنشاء Laravel scaffold، أو تغيير أي task أو index مشترك.

## المقارنة: MySQL/MariaDB مقابل PostgreSQL

Laravel يوثق `DB::transaction` و`lockForUpdate` ومحاولات إعادة المعاملة عند deadlock، لكنه لا يوحّد دلالات المحركات. |
| المفاتيح الأجنبية وscope الكيان | يدعم `InnoDB` المفاتيح الأجنبية المركبة؛ تتطلب الأعمدة المرجعية أنواعاً متوافقة وفهارس مناسبة، ويجب استخدام مفتاح `PRIMARY` أو `UNIQUE` مستقر للجهة المرجعية. | تدعم القيود المركبة والمراجع إلى مفتاح `PRIMARY` أو `UNIQUE`. | يمكن لقيد مركب يتضمن `entity_id` منع الربط بين سجلات كيانات مختلفة عند تصميم المفاتيح المرجعية المناسبة؛ هذا لا يثبت صلاحية المستخدم ولا يحل محل authorization وscope في application layer. يجب اختبار العلاقات عبر `entity_id` و`warehouse_id` صراحة. |

## UUID مقابل ULID

توثيق Laravel 12.x يذكر أن `HasUuids` يولّد `UUIDv7` افتراضياً؛ وهو 36 محرفاً في تمثيله النصي وقابل للترتيب المعجمي. `HasUlids` يولّد `ULID` بطول 26 محرفاً وقابل للترتيب المعجمي كذلك. يوفر `Schema` طرق `uuid`/`ulid` وطرق FK المقابلة؛ لكن نوع التخزين الفعلي/DDL قد يختلف بحسب driver، ولذلك لا يكفي نجاح migration على محرك واحد لإثبات التوافق. يتطلب Eloquent مفتاحاً غير رقمي إعداداً متوافقاً؛ وتُوحّد أنواع PK/FK وكل morph/serialized reference.

**اقتراح غير معتمد للـproof فقط:** اختبر `UUIDv7` عبر Laravel first-party `HasUuids` كخط أساس، وقارن `ULID` على مصفوفة التوافق نفسها إذا كان قصر المعرّف النصي مطلوباً. فرق الطول حقيقة توثيقية وليس benchmark أو دليلاً على كلفة فعلية. لا يختار هذا المقترح PK في schema ولا يجعل المعرّف سراً أو بديلاً عن authorization.

## التوصية وحالة القرار

**Recommendation: Proposed — يبقى محرك الإنتاج ومعرّف PK غير محسومين.** الأدلة المكتبية تثبت أن Laravel يدعم خيارات المحركات الثلاثة وأن كلاً منها يوفر primitives لازمة، لكنها لا تثبت ملاءمة تشغيلية أو تفوق أداء لهذا المنتج، ولا تتضمن تفضيل فريق التشغيل أو تكلفة/حملاً مقاساً. لا أوصي بترتيب MySQL وMariaDB كمحرك واحد؛ يُختبر كل منتج وإصدار كهدف مستقل.

لا يوجد حالياً تطبيق Laravel أو قاعدة بيانات مثبتة في هذه الحزمة التخطيطية. يمكن للفريق اختيار محرك disposable للتطوير/الـspike لاحقاً؛ هذا الاختيار المحلي لا يساوي قبول stack ولا اعتماد الإنتاج. دليل concurrency وbackup يجب أن يأتي من نفس database engine/version/driver المرشح للإنتاج؛ اختبار SQLite أو mock لا يثبت سباقات المحرك. يظل `Status: OPEN` حتى مراجعة `Engineering + Finance`، ومشاركة مالك التشغيل عند تحديد الاستعادة، وتسجيل الاختبارات والتوقيعات والتاريخ. لا تفك حجب implementation tasks اعتماداً على هذه التوصية وحدها.

## الأدلة والحدود وأسئلة الاعتماد

### Identifier contract and pass/fail oracle

- Canonical domain ULIDs are lowercase ASCII strings of exactly 26 characters. Validate the raw value as a string of length 26 with no trimming or coercion, then ASCII-lowercase and require full match `^[0-7][0-9a-hjkmnp-tv-z]{25}$`. Uppercase/mixed-case valid input resolves to the same canonical identifier; reject whitespace, I/L/O/U, non-ASCII, overflow first character, wrong length and numeric inputs. Generate using first-party HasUlids, whose pinned implementation lowercases output. Never infer authorization or strict global event ordering from a ULID.
- Domain PK: `CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL PRIMARY KEY`; immutable, non-incrementing Eloquent string key. Every domain FK and morph/reference ID uses the same length/charset/collation. Nullable relationships alone may be NULL; otherwise NOT NULL. Enforce lowercase/alphabet/length with a named CHECK using OCTET_LENGTH=26 and a case-sensitive REGEXP BINARY match of the canonical pattern, not a case-insensitive connection collation. Direct SQL producing a non-canonical stored value must fail; application input normalization does not replace the constraint. CHAR padding/coercion is not raw-input validation: reject overlong/trailing-space inputs before binding rather than assuming the stored-value CHECK can inspect the original input.
- For entity-owned links, enforce `FOREIGN KEY (entity_id, parent_id) REFERENCES parent(entity_id, id)` against an explicit UNIQUE(entity_id,id), with matching child index/types. Default ON UPDATE RESTRICT / ON DELETE RESTRICT; no implicit cascade of financial, audit or stock history. Domain-specific exceptions and business-key uniqueness require domain-owner review. Morph type is a stable allowlisted alias; polymorphic references require application scope/existence validation because a normal FK cannot cover multiple target tables.
- Model, route binding, JSON API, event payload, job payload and cache/search reference round-trips must preserve the canonical 26-character string byte-for-byte; no int/UUID/binary casts or silent truncation. Domain identifiers and event IDs already defined by event contracts retain their declared types; framework jobs numeric IDs and failed-job UUIDs are explicit infrastructure exceptions, not a ULID conversion project.
- Minimum identifier cases: valid lowercase round-trip through each boundary; uppercase alias normalizes to the same row; duplicate canonical PK fails; malformed values above fail; invalid direct-SQL uppercase fails; missing parent and cross-entity parent fail; valid scoped parent succeeds; delete/update of referenced PK fails. Verify metadata for PK/FK/morph columns and <=60 ASCII-byte constraint/index names. These are required future assertions, not tests executed in this documentation change.
