# ADR-006 — عقود موصلات الرسائل

Status: OPEN

Owner: Management + IT

## السياق والحدود
- يغطي `COM-01..09` فصل الرسائل الداخلية عن قنوات العملاء، وسجل الرسالة وحالتها وخصوصيتها وفشل الإرسال.
- لا اختيار لمزود أو قناة إنتاجية هنا؛ المقارنة والأدلة وأسئلة المالك في [موجز OPEN-07](../../governance/evidence/OPEN-07.md). لا أتمتة WhatsApp غير المدعومة عبر Web/QR.
- العقود التالية حدود تكامل مقترحة، وليست إعداداً أو اعتماداً أو ادعاءً بتوافق مزود.

## حدود موصلات القنوات
- **بريد الشركة:** عقد موحد للإرسال والاستقبال/المزامنة والرد والتحويل والصندوق والمرسل والمرفقات والربط بالسجل. يُقيّم مسار API كموصل صندوق/رسائل، مقابل SMTP للإرسال مع IMAP لمزامنة الصناديق والمجلدات؛ لا يفترض تكافؤ القدرات أو دعم الإيصالات. لا خيار محسوم.
- **SMS:** موصل إرسال باسم مرسل تملكه الشركة وإيصالات حالة؛ `SMS Misr` أو مزود يوافق عليه المالك، دون اختيار حالي.
- **Telegram:** موصل pilot محدود عبر التكامل الرسمي فقط، بعد opt-in/بدء التواصل، قابل للإيقاف ولا يفترض توفره لكل عميل.
- **WhatsApp:** موصل منفصل للمسار الرسمي المتوافق فقط، اختياري وخاضع لاعتماد لاحق؛ لا اعتماد أو مزود مختار.

## العقد ودورة الرسالة
- يحوي `send intent` الحد الأدنى: معرف رسالة داخلي ثابت، معرف حساب قناة مملوك للشركة، `customer_id`، القناة/الغرض، actor، مرجع النص/القالب وإصداره، `idempotency key` و`correlation_id`. يسجل مع تغيير المجال و`audit intent` و`outbox` في معاملة واحدة.
- يستهلك العامل الـoutbox عبر عقد موحد للإرسال/الاستقبال والإيصالات. قبل الإرسال يعيد فحص الصلاحية ونطاق السجل والكيان والتعيين والغرض والموافقة ومنح الحقول (`field grants`)، ثم يحل الخادم وجهة العميل من السجل؛ لا تقبل الوجهة الخام من العميل.
- تحتفظ الشركة بمعرفات حساب البريد/المرسل/الأصل، والفوترة والاسترداد والصلاحيات الإدارية. لا تعتمد ملكية الحساب أو استعادته على موظف. الأسرار ليست معرفات حساب، وتدار مشفرة وقابلة للتدوير والإلغاء.
- يسجل الرد `provider_message_id` إن توفر، ومعرف الإيصال، والحالة الموحدة: `queued`، `sending`، `accepted`، `delivered`، `failed` أو `unknown`. `accepted` يعني قبول الطلب فقط ولا يعني `delivered`.
- يحول adapter أخطاء المزود إلى فئات ثابتة: مؤقتة، دائمة/وجهة، إعداد/صلاحية، حد/تقييد، أو غير محسومة؛ يخزن رمزاً وتفصيلاً منقحاً، لا أسراراً أو بيانات وجهة. تعاد المؤقتة وفق حدّ معتمد؛ الدائمة لا تعاد آلياً، وغير المحسومة تذهب للمصالحة/`DLQ`.
- توضع webhooks والإيصالات الواردة في `inbox` مع إزالة التكرار، وربط معرف الرسالة، ومعالجة التأخر وخروج الترتيب دون ترقية/خفض حالة نهائية موثقة. يلزم التحقق من توقيع وسلامة/حداثة كل webhook وحماية replay؛ آلية التوقيع والحقول والمهلة لكل مزود `Unverified` حتى دليل رسمي.
- عند timeout بعد احتمال قبول المزود، تفحص حالة/إيصال المزود إن توفرا. وإلا تسجل `unknown` وتطلب مصالحة قبل إعادة الإرسال؛ لا إرسال أعمى ولا افتراض `exactly-once` أو أن انقطاع الرد يعني عدم القبول.

## الخصوصية والإلغاء والاحتفاظ
- لا تخزن الوجهة الخام في `outbox` أو أحداث عامة أو سجلات؛ يحلها backend عند التنفيذ ولا يكشفها إلا لموصل الإرسال المقيد. يطبق `field masking` على الوجهة والحقول الحساسة في API/العرض/الرؤوس والاقتباس والإشعارات والبحث والتعداد والتصدير وlogs/traces حيث يمكن التحكم. المحتوى الذي يكتبه العميل قد يكشفها.
- قلل المحتوى والـmetadata والمراجع إلى ما يلزم للقناة والغرض والتسوية؛ قيّد الوصول لمعرفات المزود والإيصالات. لا تنسخ payload webhook كاملاً دون ضرورة ومدة معتمدة.
- السحب/الإلغاء يمنع الرسائل غير المرسلة؛ يعاد فحص الإذن والموافقة قبل dispatch، وتلغى صلاحيات الموظف والجلسات ومنح المزود عند offboarding مع إعادة إسناد العمل. تبقى سجلات وحسابات الشركة وفق قرار الاحتفاظ في `OPEN-10`، لا وفق بقاء الموظف.

## تفضيل الحزم والقيود المعرفية
- يقيّم Laravel mail/notifications المدمج أولاً، ثم adapters موثوقة ومصانة، قبل custom plumbing. لا حزمة ثبتت أو اختيرت أو ادعي توافقها؛ لا تثبيت dependencies ضمن هذا القرار. تبقى صلاحيات المجال وحل الوجهة والإخفاء والتدقيق خارج مسؤولية الحزمة.
- إعداد المزود الحقيقي ومصادقته وscopes والأسعار وجاهزية Meta وخصائص webhook كلها `Unverified`: نص الصفحة الرسمية المتاح كان مقتطعاً وأدوات `devtools` غير متاحة. راجع [حدود أدلة OPEN-07](../../governance/evidence/OPEN-07.md#L96-L103)؛ لا يلزم بحث إضافي لهذا التقييم.
- مراجع الحدود: [PRD COM-01..09 وWhatsApp](../../product/PRD.md#L421-L462)، [تصميم الحل](../SOLUTION_ARCHITECTURE.md)، [فهرس الأحداث](../EVENT_CATALOG.md)، [استراتيجية الحزم](../PACKAGE_STRATEGY.md)، [مصفوفة الصلاحيات](../../security/PERMISSION_MATRIX.md).

## القرار والاختبارات
- القرار غير معتمد؛ لا مزود أو حساب أو صلاحيات إنتاجية مختارة. يبقى `OPEN-07` مفتوحاً، وموصلات الإنتاج محجوبة إلى اختيار `Management + IT` وتقديم الأدلة والمراجعات المطلوبة. لا تاريخ أو توقيع اعتماد.
- الاختبارات المستقبلية المطلوبة: صلاحيات/سحب قبل التنفيذ، حل الوجهة والإخفاء، عقود البريد لكل مسار، dedup وترتيب الإيصالات وتوقيع webhook، أخطاء/retry وtimeout/المصالحة، انقطاع/outbox/`DLQ`، الاحتفاظ وoffboarding. كلها `NOT RUN`؛ لا إرسال حي أو حسابات أو رموز وصول ضمن هذا العمل.
