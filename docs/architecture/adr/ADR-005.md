# ADR-005 — Mobile delivery

Status: OPEN

## النطاق والحالة
هذا تقييم قابل للتنفيذ، لا اختيار منصة أو تصميم واجهة أو إذن تنفيذ تطبيق. دور صاحب القرار وفق [OPEN-08](../../governance/evidence/OPEN-08.md): `Engineering`؛ لا اسم/إقرار/توقيع/تاريخ قبول مسجل. تبقى تفاصيل مصفوفة الأجهزة والاختبارات في OPEN-08 ولا تُكرر هنا.

## القيود والآثار المعمارية المشتركة
- الويب والجوال يستعملان `API` موحداً وخدمات المجال/التطبيق نفسها؛ التفويض على الخادم لكل طلب وسجل/كيان/حقل، مع نفس القيود وسير الموافقات والتدقيق ومنع الرفض. لا يمنح العميل دوراً ولا يطبق قواعد مجال مستقلة. [PRD: المنصات والخصوصية وAPI](../../product/PRD.md#L22-L34) · [المعمارية](../SOLUTION_ARCHITECTURE.md#L18-L29)
- العربية `RTL` هي واجهة الإنتاج؛ تستخدم العملاء مفاتيح ترجمة مشتركة، وعزل `bidi`، وتنسيق التاريخ/العملة المحلي مع حفظ الوقت `UTC` وعدم استخدام `float` للمال. لا تُفرّع قواعد اللغة/المجال بين الويب والجوال. [PRD: NFR-06 وAT-13](../../product/PRD.md#L650-L652) · [AT-13](../../product/PRD.md#L737-L739)
- الخصوصية تشمل `UI` و`API` والبحث والتنزيل والإشعار؛ أعد التفويض عند الطلب، واخفِ البيانات الحساسة من معاينة الإشعار والسجلات. الجلسات/الاعتمادات قابلة للإلغاء؛ إنهاء الخدمة يسحبها على الخادم. [PRD: SEC-02/06 وNFR-01](../../product/PRD.md#L113-L135) · [NFR-01](../../product/PRD.md#L630-L632)
- افحص المصادقة حسب العميل الفعلي: متصفح أولي/`PWA` يقارن جلسة خادمية وcookie آمنة قابلة للإلغاء (مع `CSRF`) بتخزين bearer token في المتصفح؛ عميل `native` مستقل يقارن جلسة إن دعمتها البنية مع token قصير العمر قابل للإلغاء وتجديد مضبوط وتخزين نظام محمي. في `hybrid` يحسم نمط `WebView`/عميل API أيهما ينطبق؛ لا تكشف سر الجلسة أو token لجسر أو `JavaScript`. في جميع الحالات أعد فحص `authz` لكل طلب، واختبر الانتهاء والخروج والسحب وإلغاء الجلسة. هذا تقييم لا اختيار مصادقة.
- التقط الصورة/التوقيع كدليل غير نهائي؛ لا يثبت بدء الالتقاط أو استجابة النقل اكتمال المهمة. أعد المحاولة بنفس `idempotency key` للعملية والحمولة؛ تكرار الحمولة نفسها يعيد النتيجة/مرجع المرفق نفسه، واختلاف الحمولة للمفتاح نفسه يُرفض. إن كان الإكمال callback/event غير متزامن، deduplicate على الخادم بمعرف الحدث/العملية وتحقق من الحالة والصلاحية؛ لا تثق بإشعار العميل وحده. لا يعرض العميل `accepted/completed` إلا بعد تأكيد الخادم وحصوله على مرجع مرفق صالح وحالة نهائية.
- لا `commit` مالي أو مخزني دون اتصال، ولا طابور يعيد نشره تلقائياً عند عودة الشبكة؛ أي عملية مالية/مخزنية تتطلب اتصالاً وتحققاً وموافقة خادمية. لا يُفترض حفظ محلي لمسودات أو ملفات حساسة قبل سياسة خصوصية/أمن معتمدة. [NFR-02/05](../../product/PRD.md#L634-L648)

## البدائل وآثارها — دون اختيار
- **Responsive web:** يفي بمتطلب الويب المتجاوب ويمكنه بدء المسارات الحرجة على عقد API المشتركة؛ اختلاف دعم الكاميرا/الملفات/الخلفية والإشعارات بين المتصفحات يفرض مصفوفة دعم واختباراً فعلياً.
- **PWA:** تسليم ويب قابل للتثبيت، لا ضمان لتكافؤ وظائف التطبيق؛ lifecycle والتخزين والإذن والإشعارات تابع للمتصفح/النظام. لا يغير حدود API أو يجيز offline commit.
- **Hybrid:** مشاركة واجهة الويب ممكنة، لكن جسر الجهاز/الإضافات يضيف حد ثقة وصلاحيات وإصدارات يجب اختبارها، مع بقاء المجال والتفويض على الخادم.
- **Native:** تكامل نظام محتمل، مقابل بناء/إصدار ومصفوفة دعم واختبار لكل نظام وعميل مستهدف؛ لا يثبت الاسم وحده أمان التخزين أو نجاح الالتقاط/الرفع.
- هذه آثار تقييمية لا نتائج أجهزة. قارن الحالات والأجهزة والتجارب التفصيلية في جدول وخطة [OPEN-08](../../governance/evidence/OPEN-08.md#L14-L72)؛ لا توجد حالياً نتيجة تثبت أفضلية خيار. لا يرشح هذا السجل framework أو package للجوال؛ لم يُتحقق من توثيق رسمي لمرشح محدد، ولا اعتماد/تثبيت dependency.

## بوابات التقييم قبل توصية/قبول لاحق — كلها `NOT RUN`
1. تسجل `Operations` أجهزة الأسطول والمسارات/الأدوار الحرجة؛ يختبر `Engineering` كل تركيبة فعلية يريد إعلان دعمها (طراز، نظام، متصفح/وضع تثبيت أو بناء). لا تُخترع أجهزة أو إصدارات، ولا يكفي المحاكي؛ غير المتاح يسجل غير مختبر/غير مدعوم.
2. على الويب وكل تركيبة معلنة، أثبت تكافؤ المسارات الحرجة المصرح بها وحالات الرفض (سجل خارج النطاق، صلاحية مسحوبة، انتقال مرفوض)، إخفاء الحقول، التدقيق، انتهاء/إلغاء الجلسة وعدم بقاء اعتماد قابل للاستعادة. راجع `AT-13`: عربية `RTL` والأرقام والجداول والحوار والنماذج بلا overflow، مع مراجعة لوحة المفاتيح/التركيز على الجهاز.
3. اختبر أذونات الكاميرا/الملفات/التوقيع والرجوع من الخلفية؛ اقطع الشبكة قبل الإرسال وبعد قبول الخادم، وكرر upload/callback، وأثبت عدم إنشاء مرفق/نشاط/انتقال مزدوج وأن العرض لا يسبق تأكيد الخادم؛ أرسل نسخة قديمة/متزامنة وأثبت تعارضاً صريحاً دون كتابة صامتة.
4. افصل الشبكة وحاول عمليات مالية/مخزنية معتمدة للاختبار: يجب ألا يتغير سجل الخادم وألا تظهر نجاحاً أو تُنشر بعد الاتصال. سجّل نتائج الفشل والعيوب وإعادة الاختبار؛ لا تُخترع عتبات قبول. استخدم تفاصيل الحالات/الأدلة في [OPEN-08](../../governance/evidence/OPEN-08.md#L49-L72) ومصدر معيار [AT-13](../../product/PRD.md#L737-L739).

## أثر التنفيذ والحسم
يمكن مواصلة مسارات الويب الحرجة على `API` والعقود والضوابط المشتركة دون انتظار اختيار التطبيق الأصلي النهائي. لكن لا يُغيّر scaffold أو بوابات الاختبار أو افتراضات المصادقة/التخزين بصمت؛ أي تغيير يتطلب قراراً/نطاقاً موثقاً ومصرحاً به. تبقى توصية المنصة وحدود دعمها مفتوحة إلى اكتمال أدلة الأجهزة ومدخل `Operations` ومراجعة الأمن/التشغيل وقرار `Engineering` الصريح؛ لا تتحول هذه المقترحات إلى موافقة إنتاجية أو تحديث لسجلات المهام.
