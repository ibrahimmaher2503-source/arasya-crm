## النطاق والسياق المؤكد

هذا تقييم وتوصية لـA0-ADR-003، لا اعتماد تنفيذ أو إنتاج. خيار Laravel مؤكد؛ إصدار Laravel/PHP وقاعدة البيانات والاستضافة وسعات الإنتاج ما زالت OPEN. وثائق Laravel 12.x أدناه تثبت وجود آليات موثقة فقط، ولا تثبت توافق إصدار مستهدف.

- يحدد [تصميم الحل](../SOLUTION_ARCHITECTURE.md) قاعدة بيانات علائقية للكتابة، outbox داخل معاملة التغيير، نشر بعد commit، وinbox dedup مع أثر المستهلك في معاملة؛ التسليم at-least-once وليس exactly-once عبر الشبكة.
- تحدد [عقود الأحداث](../EVENT_CATALOG.md) حمولة قليلة البيانات، `event_id` ثابتاً عند إعادة النشر، dedup/reconciliation وDLQ؛ وسياسة الاحتفاظ وإعادة التشغيل وSLOs مفتوحة.
- يؤكد PRD البحث المصرح فقط، إخفاء بيانات الاتصال في البحث والتصدير، وظائف الخلفية وإعادة المحاولة، واحتياج قياس الحجم والتزامن والأهداف قبل اختيار الاستضافة. راجع [PRD](../../product/PRD.md) و[مصفوفة الصلاحيات](../../security/PERMISSION_MATRIX.md).
- تفضيل المستخدم package-first: آليات Laravel المدمجة/first-party قبل نقل queue مخصص؛ لا package أو محرك هنا معتمد. [استراتيجية الحزم](../PACKAGE_STRATEGY.md).

## التوصية المقترحة — ليست قرار قبول

اعتماد خط أساس database-first للتصميم والتجربة الأولية: queue وcache بآليات Laravel المدعومة بقاعدة البيانات، وبحث من قاعدة البيانات باستعلامات وفهارس مناسبة بعد حسمها. لا تُنشأ آلية نقل queue مخصصة. يبقى cache غير سلطوي، وتُقيّم Scout/database engine كمرشح بحث لا كاعتماد. لا يُنقل الإنتاج إلى Redis أو محرك بحث منفصل إلا بعد ظهور حاجة في workload واقعي، مراجعة أمن وتشغيل واحتفاظ، واختبارات قبول؛ هذا التقييم ليس إذناً للنشر.

## مصدر الحقيقة والخصوصية والتسليم

- قاعدة بيانات المجال هي مصدر الحقيقة الوحيد للكتابة والقرارات. cache وsearch index قراءات مؤقتة/ projections قابلة لإعادة البناء؛ لا تُقبل كمرجع للمال أو المخزون أو الصلاحية أو حالة workflow.
- تُكتب outbox row مع تغيير المجال وaudit intent في transaction واحدة؛ ينشر worker بعد commit. يسجل كل consumer inbox/dedup ومفعوله في transaction واحدة حيث ينطبق، مع تحقق version/reconciliation عند الترتيب غير المتوقع.
- كل queued work يعيد التحقق وقت التنفيذ من الصلاحية الحالية، entity/assignment scope والغرض ونسخة السجل؛ لا تعد هوية الفاعل أو صلاحيات وقت enqueue تفويضاً دائماً. تُسجل حالات الرفض بأمان.
- تُطبق صلاحيات السجل وfield masking على نتائج البحث، الاقتراحات، counts والتصدير في الخادم، لا في الواجهة فقط. يجب أن تعزل مفاتيح cache البيانات حسب scope المستخدم/الكيان والسياسة، وألا تخزن حقول اتصال مكشوفة أو تعيد قرار authorization بعد إلغاء الصلاحية.
- صمم idempotency keys وdedup وإعادة محاولة محدودة بجدولة مناسبة وDLQ بسبب منقح، مع replay مُصرح ومسجل يحافظ على `event_id`؛ عالج out-of-order وstale projections بالمصالحة أو إعادة البناء. استخدم idempotency لدى provider إن دعمها، وسوِّ الحالات الملتبسة قبل الإعادة. لا يُدّعى exactly-once لأي أثر شبكي خارجي.
- عند النشر أو الإيقاف، أوقف استقبال jobs جديدة، ودع الجاري ينتهي أو يُنهَ بأمان وفق timeout/lease مع حفظ قابليته لإعادة المحاولة؛ إثبات worker drain جزء من اختبار التشغيل، لا افتراضاً.

## نطاق التطوير المحلي والإنتاج

يمكن ضبط بيئة المطور محلياً بشكل مستقل لاختبار قاعدة البيانات أو Redis عند الحاجة. اختيار container محلي أو نجاح smoke test لا يختار backend الإنتاج ولا يثبت سعة أو أمن أو توافره. يلزم اختبار production configuration منفصل قبل اعتماد المحرك.

## أدلة واختبارات مطلوبة لاحقاً — لم تُنفذ هنا

قبل القبول، نفذ واوثق اختبارات race والتزامن (تنافس enqueue/publish، duplicate/out-of-order، إلغاء أو تغيير الصلاحية قبل تنفيذ job، ونسخ projection المتزامنة)، crash/failure (قبل commit وبعده، بعد النشر وقبل حفظ inbox، توقف worker أثناء job، انقطاع Redis/DB أو search، وdrain أثناء النشر)، وreplay/recovery (retry، DLQ ثم replay بنفس `event_id`، إعادة بناء الفهرس، reconciliation للحالة الملتبسة)، واختبارات provider (رفض/timeout/نجاح مع انقطاع الرد، وتحقق أثر الإرسال من دون ادعاء exactly-once). أضف اختبارات تسرب scope/masking للبحث والعدد والتصدير، والإلغاء/الإخفاء والحذف، والقياس على أحجام وتزامن وافتراضات المنتج الفعلية.

هذه الاختبارات المستقبلية **NOT RUN** في هذا التقييم؛ لا توجد نتائج performance أو crash/replay/provider أو security leakage ميدانية.

## متطلبات مفتوحة قبل اختيار الإنتاج أو القبول

1. **السعة:** OPEN-11؛ عدد المستخدمين والبيانات والـjobs ومعدلات الذروة والتزامن، مؤشرات backlog/lag والتفاعل، وأهداف availability وRPO/RTO، مع workload وملف قياس متفق عليه. لا أرقام متوقعة مفترضة هنا.
2. **الأمن:** نموذج التهديد ومراجعة إعدادات الشبكة وTLS/التشفير، أسرار الخدمة وleast privilege/ACL، عزل tenants إن ظهرت مستقبلاً، إلغاء الوصول، سياسات الفهرسة وحقول البحث، والتدقيق ومنع تسرب البيانات من jobs/cache/logs. يلزم owner/sign-off أمني.
3. **الاحتفاظ والاستعادة:** OPEN-10؛ مدد وحذف/أرشفة outbox/inbox وfailed jobs/DLQ وcache وsearch projections والنسخ والسجلات؛ صلاحية وسبب replay، استعادة واختبار حذف البيانات الشخصية. يلزم owner/sign-off قانوني وتشغيلي.

## Executable qualification contract — 2026-10-17

Engineering qualification defaults below refine the approved database queue/cache/scoped SQL-search direction. They are specification choices for role review, not new approvals or applied configuration. Use the exact [ADR-002 platform and identifier contract](ADR-002.md#executable-qualification-contract--2026-10-17). All target-11.4.13 and application criteria below are **NOT TESTED**. Prior 10.4 synthetic evidence remains historical; no acceptance or task state changes.

| Area | Qualification default / enforceable boundary | Minimum future pass/fail evidence |
|---|---|---|
| Queue transaction boundary | Laravel database queue; domain mutation + audit intent + outbox in one InnoDB transaction. Publisher reads committed outbox; any direct transactional dispatch uses after_commit=true or explicit afterCommit. Cache/search are not authoritative. | Rollback creates no visible job/effect; committed outbox survives publisher crash; restart republishes same event_id. Consumer inbox UNIQUE(consumer,event_id) and its domain effect commit atomically. Crash before/after each boundary and duplicate delivery leave one committed effect. |
| Attempts/backoff/failures | Three total processing attempts; exception backoff 5s then 30s, no unlimited retry. Permanent denial/invalid payload fails without domain mutation. Timeouts consume attempts; unknown external outcomes pause for reconciliation instead of blind retry. failed_jobs uses database-uuids; replay selects failed_jobs.uuid with queue:retry <uuid>, never its numeric row ID. | Force transient failure twice then success; exhaust third attempt and observe failure; numeric-ID replay cannot be reported as successful; authorized UUID replay actually executes. Log sanitized SQLSTATE/vendor error, child stdout/stderr, exit, timeout and failed assertion; omit secrets/raw payloads. |
| Lease and timeout | Database retry_after=90s; worker/job timeout=60s maximum, DB lock wait budget=5s, external connection timeout=5s and total call timeout=20s. All blocking operations bounded within the job budget. No per-job override may violate timeout < retry_after. Use long-running queue:work, not --once, for timeout proof. | Kill/hang a worker: no second reservation before 90s; abandoned job becomes reservable afterward. Show a timed-out process has exited before lease expiry. Reclamation does not imply exactly-once effects; dedup and locked version checks remain mandatory. |
| Ownership locks | If an overlap/cache lock is used, shared DB store, unique owner token, TTL=90s, release by owner only; never force-unlock a live owner. The lock is not a domain invariant or authorization check. | Wrong-owner release fails; expired lock recovers; a stale worker cannot commit a duplicate/stale effect. Reject longer-running jobs pending a reviewed timeout/lease profile. |
| Replay and execution authorization | Replay denied by default until Security/domain owner name the permission and allowed scope. Authorized request records actor, reason, failed-job UUID, event_id, entity and request time in durable audit before dispatch, then appends execution outcome/time afterward. Re-check current actor/entity/assignment/purpose/record-version authority at execution; enqueue-time roles are insufficient. | Denied replay enqueues nothing; revoked or cross-entity actor cannot mutate; approved replay preserves event_id/idempotency and dedup. No shell access or raw queue:retry is evidence of an application authorization policy. Ambiguous provider success requires reconciliation first. |
| Supervision/drain/recovery | Proposed qualification host: Linux with PCNTL/POSIX, one supervised worker, automatic restart after 5s on unexpected exit; process-group shutdown grace=75s. Job timeout 60s < stop grace 75s < lease 90s. Supervisor or equivalent must reap the process group; no new attempts from a stopping worker. Pause producers/consumers for controlled drain and stop/restart by IT/Operations procedure. | TERM drains current work; forced kill recovers after lease; child process group exits within grace; restart only after previous process exit; restart/cache-signal failure is reported. DB outage leaves work durable for recovery; bounded shutdown, replay and backlog evidence recorded. No supervisor installed here. |
| Cache | Laravel database cache/locks in isolated namespaced tables; disposable read-cache TTL=60s, no forever cache for sensitive reads. Keys include entity, actor/effective scope, policy version and data version; authorize on every read, invalidate on mutation/revocation/delete. Store minimum masked scalars/arrays; no raw contact values/secrets or unserialized PHP objects. | Cross-scope key cannot hit; expired/revoked/deleted data not returned even before TTL; cache failure falls back to authorized DB read, or denies if authoritative policy cannot be checked. Flush/rebuild does not change business state. |
| SQL search/projections | Indexed MariaDB SQL; server-side scope/masking applies before results, suggestions, counts, pagination and export. Bind all values, allowlist sort/field names. Source DB remains authority; projection upsert requires increasing aggregate version; stale/out-of-order events reconcile rather than overwrite newer data. | Duplicate/reordered events do not regress projection; revoke/delete suppresses data across result/count/export immediately through source-policy checks. Rebuild from source reproduces authorized results; empty unauthorized output leaks no counts/contacts. No full-text/Arabic relevance or performance sufficiency claim without approved workload. |

These numbers are chosen lab defaults, not measured service SLOs or permission/retention decisions. They require Engineering review; IT/Operations must approve production timeout, supervision, monitoring and recovery sizing. Current config/queue.php has database retry_after=90 but after_commit=false; documentation does not change it or assert compliant dispatch paths. Windows PHP has no PCNTL; the prior queue fixture and --once/--stop-when-empty behavior cannot qualify hard timeout/signals on this target. First-party Laravel mechanisms remain preferred; no custom queue transport, Redis or search service is introduced.
