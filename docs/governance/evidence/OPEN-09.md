# OPEN-09 — موجز قرار تنفيذي وأمني لمراجعة AI

> **الحالة: OPEN — دليل وخيارات للمراجعة، لا اعتماد أو سياسة نافذة.**
> **المهمة:** `A0-OPEN-09` — **المالك:** Executive + Security.
> **نقطة الحجب:** قبل إرسال أي بيانات AI إلى جهة خارجية أو تفعيل معالجة AI.
> **النطاق:** جمع خيارات ومتطلبات الأدلة فقط؛ لا اختيار مزود/نموذج/منطقة أو توقيع اتفاق.

## 1. خلاصة القرار المطلوب

لا مزود أو نموذج أو منطقة معالجة أو DPA أو مدة احتفاظ أو ميزانية معتمدة في الأدلة المقروءة. تبقى جميعها `TBC`. لا يُرسل محتوى عميل أو موظف أو مستند إلى أي مزود قبل مراجعة قانونية وأمنية واعتماد صريح وأدلة تقييم. هذا الموجز لا يوصي بخيار بعينه ولا يرفع حجب `OPEN-09`.

| بند قرار المالك | المطلوب إثباته قبل الاختيار | الحالة |
|---|---|---|
| الاستضافة/المزود والنموذج | مقارنة مرشحين محددين وقدرتهم على حالات PRD، ودعم نسخة/معرّف قابل للتدقيق | `TBC` — لا اختيار |
| منطقة المعالجة | مناطق inference والتخزين والسجلات والنسخ والدعم، وsubprocessors ومسارات النقل | `TBC` — لا منطقة معتمدة |
| DPA والمعالجة | مراجعة Legal لنطاق المعالجة، التدريب، الاحتفاظ/الحذف، الحوادث، التدقيق والمقاولين | `TBC` — لا اتفاق مثبت |
| الاحتفاظ | مدد منفصلة للمدخلات والمخرجات والسجلات والنسخ/المراجع، مرتبطة بسياسة `OPEN-10` | `TBC` — لا مدة معتمدة |
| الميزانية | سقف وفترة وعملة، تكلفة كل مراجعة/شهر، قياس الاستخدام وحد إنذار/إيقاف | `TBC` — لا عرض أو اعتماد |
| فئات المراجعة والأولوية | إقرار الأولوية أدناه وحدود كل فئة بعد تقييم عينات | PRD يحدد ترتيبًا أوليًا؛ لا اعتماد إنتاجي |

## 2. بدائل الاستضافة — مقارنة قدرة/مخاطر، لا ترشيح

| البديل | قدرة محتملة يلزم إثباتها | مخاطر ومتطلبات لا يجوز افتراض حسمها |
|---|---|---|
| Hosted model API | إدارة الاستدلال من جهة الخدمة قد تسرّع التجربة؛ القدرات والجودة والكمون تعتمد على المرشح وتُقاس على الحالات المنقحة نفسها. | نقل البيانات لطرف ثالث؛ المنطقة الفعلية وsubprocessors والدعم والسجلات والنسخ؛ شروط التدريب/الاحتفاظ والحذف وDPA؛ انقطاع الخدمة والتغير/الاعتماد على المزود والتكلفة. لا يرسل هذا العمل أي طلب API. |
| نموذج self-hosted معتمد | قد يتيح تحكمًا تشغيليًا أكبر إذا أثبتت Arasya مكان التشغيل، العزل ومنع egress وإدارة السجلات؛ القدرة والجودة ليستا مفترضتين. | لا يوجد نموذج أو بيئة معتمدان حاليًا؛ يلزم إثبات الترخيص والقدرة والجودة، والتحديثات والثغرات والمراقبة والسعة والنسخ والاستجابة والموارد والتكلفة التشغيلية. Self-hosted لا يثبت وحده عدم انتقال البيانات أو الامتثال. |

يقارن المالك الخيارين على مجموعة الاختبار ذاتها، بعد تنقيحها، مع قياس الجودة لكل فئة والكمون والكلفة، وإثبات المنطقة والتدفق والعقد والضوابط وخطة الخروج. لا يكفي وصف تسويقي أو اختبار عام لإثبات الملاءمة.

## 3. ترتيب التدقيق المقترح من PRD

هذا ترتيب أولي وارد في PRD، وليس اعتمادًا لفئات أو عتبات تشغيل:

- **P0:** المصروفات والعمولات — مثل المصروف المكرر، خلل الموافقة، أو عمولة على بيع ملغى.
- **P0:** عروض الأسعار والعقود — بند مفقود، إجماليات غير متسقة، خصم/هامش غير معتاد.
- **P0:** المشاريع والمخزون — صرف يتجاوز الحاجة المعتمدة أو تجاوز تكلفة المشروع.
- **P1:** التسليم والجودة — إثبات تسليم موقع أو فحص غير مكتمل.
- **P1:** متابعة العملاء والأداء — متابعة فائتة متكررة أو إسناد تحويل غير معتاد.

يؤكد مالك العمل نطاق كل فئة وتعريف finding وأولوية الإصدار. لا يحول الترتيب أي finding إلى منع أو موافقة آلية.

## 4. حدود بيانات وأمن المعالجة

- **تفويض قبل الاختيار:** طبّق authorization وentity/record/field scope على الخادم قبل بناء المدخل. أرسل allowlist ضيقة حسب الغرض والفئة والنسخة؛ لا تجمع حقولًا أو وثائق كاملة لمجرد توافرها.
- **تقليل وتنقيح:** احذف الأسرار والرموز وبيانات الاتصال/الهوية غير اللازمة؛ استخدم مقتطفات أو حقولًا منقحة ومراجع evidence محدودة. اختبر إزالة التعرف؛ المنقح يبقى مقيدًا حتى يثبت الاختبار خلاف ذلك. لا تحفظ raw prompts في السجلات الاعتيادية.
- **محتوى غير موثوق:** الرسائل والوثائق/المرفقات بيانات لا تعليمات. اعزلها/حددها كمدخل غير موثوق؛ لا تسمح لنص يطلب تجاهل السياسة أو كشف بيانات بتغيير التعليمات أو النطاق.
- **لا أدوات ذات امتياز:** لا privileged tool invocation ولا أوامر/اتصالات تنفذها المخرجات. لا موافقة أو دفع، ولا mutation للدفتر المالي أو العمولة أو المخزون. AI يقدم finding استشاريًا فقط؛ أي إجراء منفصل يمر عبر authorization وdomain guards والموافقات الحتمية.
- **ثوابت حتمية:** تحقق الصلاحية والحقول المطلوبة والتوازن المالي وحدود المخزون والانتقالات والموافقات ومفاتيح التكرار في الخدمات الحتمية قبل أي إجراء. تعطل AI لا يتجاوزها ولا يعطلها.
- **الانقطاع:** سجّل `unavailable/pending` مع السبب والوقت، وأعد المحاولة أو وجّه للمراجعة البشرية وفق workflow المعتمد؛ لا تعامل غياب AI كنجاح أو كإعفاء من guard حتمي.

## 5. التدقيق والنتائج البشرية

لكل تشغيل/نتيجة: correlation ID، provider/model ومعرّف/نسخة النموذج إن اختير، منطقة التشغيل، prompt/rule/template version، وقت التشغيل، input hash أو secure reference، evidence pointers وإصداراتها، output ودرجة عدم اليقين، usage/cost، ونتيجة التقييم. تحفظ المراجع والـhashes مع وصول مقيد وسياسة احتفاظ معتمدة؛ لا تُنسخ PII إلى audit/log بلا ضرورة.

يرتبط finding بالكيان ونسخته والمحفّز والأدلة وملخص السبب والخطورة وعدم اليقين والخطوة المقترحة. لكل disposition إنسان مخول يسجل الحالة والقرار/السبب والفاعل/الصفة والوقت ونسخة policy/evaluation. أي تغير في نسخة الموضوع يستلزم إعادة مراجعة finding القديم. قبول finding لا ينفذ معاملة ولا يعد موافقة مالية/مخزنية.

## 6. طلب مجموعة تقييم منقحة وعتبات القبول

يقدم مالكو الأعمال/المراجعة أمثلة **منقحة أو مصطنعة فقط** لكل فئة P0/P1: حالات إيجابية وسلبية، نسخة حقول مسموحة، label مراجع، rationale، evidence pointer منقح، والحالات الحدودية/المتناقضة. لا تُرسل بيانات عميل حقيقية أو بيانات اعتماد أو tokens أو وثائق خام إلى النموذج أو تُدرج في ملف التقييم. توثّق طريقة التنقيح ومراجع label وإصدار المجموعة وتقسيمها، وتراجع المجموعة قبل الاستخدام.

| مقياس/عتبة يقرها المالك لكل فئة | القيمة الحالية |
|---|---|
| False positive وFalse negative (تعريف/مقام/تحليل حسب الفئة) | `TBC` — لا قيمة أو نتيجة قياس |
| حد الجودة/الثقة وما يستدعي human review أو تعطيل audit | `TBC` — لا pass bar معتمد |
| حد latency المناسب للمراجعة المتزامنة والمجدولة | `TBC` — لا قياس أو هدف |
| حد الكلفة لكل مراجعة/فترة وسقف شهري وإنذار/إيقاف | `TBC` — لا عرض أو ميزانية |

يحدد Executive/المراجعون المعنيون عتبات قابلة للقياس قبل اعتماد التقييم؛ يراجع مالكو الأعمال جودة labels، وتُوثق النتائج والقيود لكل نسخة نموذج/Prompt. لا تُختلق نسبة نجاح أو سعر أو هدف latency في هذا brief.

## 7. اختبارات ما قبل التفعيل — لم تُنفذ

**NOT RUN:** اختبارات انقطاع/timeout/مخرجات غير صالحة وحد الكلفة وإعادة المحاولة؛ prompt injection من وثيقة/رسالة يطلب تجاوز السياسات أو استدعاء أداة؛ ومحاولات scope بكيان/سجل/حقل/assignment غير مصرح. كما يلزم إثبات رفض أي استدعاء امتيازي أو تغيير مالي/مخزني، واستمرار الحواجز الحتمية أثناء تعطل AI. تنفذ الاختبارات على fixtures منقحة/مصطنعة، وتثبت الحالة قبل/بعد وoutbox/audit وعدم الأثر الجانبي. هذه المذكرة لم تثبت تشغيل اختبارات تطبيقية.

لم تثبّت هذه المهمة نموذجًا أو أداة مزود، ولم تستدعِ API، أو تستخدم token، أو ترسل بيانات إلى مزود. لا يعد ذلك دليلًا على نجاح اختبارات الأمان أعلاه.

## 8. مدخلات واعتمادات لازمة — لا توقيعات مدخلة

| المالك/المراجع المطلوب | القرار أو الدليل المطلوب |
|---|---|
| Executive + Security (مالكا OPEN-09) | اختيار/رفض مسبب، المنطقة والنموذج/المزود أو قرار عدم استخدامه، فئات audit والمخاطر المتبقية، الميزانية والعتبات؛ تاريخ ودليل اعتماد |
| Legal | مراجعة DPA وشروط المعالجة/النقل والتدريب والاحتفاظ والحذف وsubprocessors؛ تحديد ما يلزم اتفاقه قبل الإرسال |
| IT/Engineering والجهة المعنية بالتشغيل | مخطط data flow، region proof، ضوابط access/egress/logs/secrets، قياس السعة والكمون والكلفة وخطة outage/exit |
| مالكو البيانات/المراجعة ومالكو الأعمال | مجموعة حالات منقحة وlabels/evidence، اعتماد تعريف FP/FN والعتبات والأولويات ومسار disposition البشري |
| مالكو `OPEN-10` عند انطباقها | حسم مدد الاحتفاظ والأساس/النطاق ذي الصلة؛ تبقى القيم مجهولة حتى اعتمادهم |

**قوالب التوقيع/السياسة المطلوبة:** سجل قرار مزود/نموذج/منطقة؛ DPA وتعليمات المعالجة؛ سياسة حقول AI والتنقيح والاحتفاظ؛ rubric/نسخة حالات التقييم وعتباتها؛ إجراء مراجعة/disposition وkill switch؛ سقف التكلفة ومراقبته؛ نتائج اختبارات الأمن مع المالك والتاريخ. كلها غير معتمدة في هذا الملف.

**الحالة النهائية:** `OPEN-09 = OPEN`. لا يوجد owner sign-off أو DPA أو region/model/provider أو budget أو retention/threshold sign-off موثق. لا تفعيل ولا إرسال خارجي إلى أن تكتمل المدخلات والأدلة والاختبارات والموافقات؛ status وحده لا يرفع الحجب.
