# ADR-007 — AI provider and privacy

Status: OPEN

Owner: Executive + Security

## السياق والقيود المثبتة
- يفرض PRD ضوابط حتمية قبل AI، ومراجعة معاملات استشارية، وتقليل البيانات المصرح بها، وتتبع الإصدارات والتقييم؛ لا تفويض لتنفيذ AI مستقل.
- `OPEN-09` لا يثبت مزوداً أو نموذجاً أو منطقة أو عقداً أو ميزانية أو عتبات؛ يمنع إرسال بيانات للخارج أو تفعيل المعالجة حتى اعتماد الأدلة. `OPEN-10` لا يحدد احتفاظاً أو أساساً أو موافقة؛ لا نفترض أياً منها.
- هذا التوسيع يحدد حدوداً ومعايير تقييم فقط؛ لا يختار مزوداً أو منطقة أو إصداراً ولا يرفع الحجب أو يجيز الإنتاج.

## حدود الواجهة والبيانات المقترحة — غير معتمدة
- تنشئ طبقة التطبيق طلباً typed من read model مصرح ومصغّر: تحقق خادمي من المستخدم والكيان والسجل والإسناد والحقول قبل تكوينه؛ allowlist حسب الغرض والفئة والنسخة. لا وصول للمزود إلى قاعدة البيانات، ولا تمرير مستند/رسالة كاملة أو بيانات غير لازمة. ما تعذّر تفويضه أو تقليله لا يُرسل.
- واجهة يملكها التطبيق تفصل حالات الاستخدام عن SDK/API الخاصين بالمزود. adapter البنية التحتية وحده يترجم العقد، ويحصر الأسرار والاتصال والمهلات وإعادة المحاولة وبيانات الاستخدام؛ لا تدخل معرفات المزود في معرفات الأعمال. يمنع تكرار الطلب أو إعادة المحاولة أثراً جانبياً.
- مخرج typed، ذو schema version معلومة: `subject_id/version`، فئة finding، evidence pointers مسموحة، ملخص سبب، severity، confidence/uncertainty، واقتراح خطوة تالية. لا يحتوي أوامر أو استدعاءات tools. ترفض الحقول/الأنواع/الإصدارات غير المطابقة أو المخرجات الناقصة كـ`invalid`؛ لا تخمين أو تحويل صامت، وتُحال للمراجعة البشرية حسب الإجراء المعتمد.
- كل finding استشاري؛ لا privileged tool execution، ولا موافقة/رفض أو دفع أو تعديل ledger/commission/stock أو كشف بيانات. أي عمل مستقبلي منفصل يمر عبر المصادقة والتفويض والتحقق الحتمي والمعاينة والموافقة وسجل التدقيق.
- انقطاع النموذج أو تعطيله لا يغيّر ولا يتجاوز أي deterministic gate. تسجّل المراجعة كـ`unavailable/pending` لا كنجاح؛ المسار البشري/أثر التأخير تحدده سياسة معتمدة، وليس fail-open. لا يحوّل غياب AI نتيجة قاعدة حتمية إلى سماح.
- سجل محدود الوصول لكل تشغيل: `correlation_id`، subject/entity ونسخته، provider/model/version إن اختير، prompt/rule/schema version، input hash أو secure reference وإصدارات الأدلة، الأوقات والكمون، usage وcost/عملة أو فجوة قياس معلنة، النتيجة، إصدار/نتيجة التقييم، وهوية المراجع المخول وقراره وسببه ووقته. لا تحفظ raw prompt أو PII في السجلات الاعتيادية؛ الاحتفاظ والتصدير وفق `OPEN-10` بعد اعتمادها.

## الاستضافة — مقارنة قدرة/مخاطر، دون ترشيح
| الخيار | قدرة محتملة تحتاج إثباتاً | مخاطر/مجهولات لا تحسمها هذه الوثيقة |
|---|---|---|
| Hosted API | قد يقلل عبء تشغيل الاستدلال ويسرّع التجربة؛ الجودة والكمون والقدرات تحتاج قياساً على مجموعة منقحة. | نقل لطرف ثالث، منطقة inference والسجلات والنسخ وsubprocessors، تدريب/احتفاظ/حذف وDPA، تغيّر الخدمة، الانقطاع والكلفة؛ جميعها `Unknown/TBC`، ولا إرسال API هنا. |
| Self-hosted | قد يزيد التحكم التشغيلي بمكان المعالجة وegress إذا ثبت العزل والتهيئة. | لا نموذج أو بيئة مثبتان؛ جودة/ترخيص/سعة، تحديثات وثغرات، مراقبة واستعادة وموارد وتشغيل وكلفة كلها تحتاج دليلاً. الاستضافة الذاتية لا تثبت وحدها الخصوصية أو الامتثال. |

لا مزود أو منطقة أو نموذج أو إصدار مختار. تقارن الخيارات على حالات منقحة واحدة مع جودة كل فئة والكمون والكلفة وتدفق البيانات والضمانات وخطة الخروج؛ لا تُعامل الأوصاف التسويقية كدليل.

## تقييم الحزم — package-first بعد اتفاق الاحتياجات
بعد الاتفاق على stack الفعلي والعقود والاحتياجات، يُقيّم Laravel AI client رسمي أو adapter package maintained كمرشح مقابل واجهة التطبيق، ثم يقارن بالخيار المخصص. التوفر والصيانة والتوافق والسلوك الأمني وملاءمة PRD كلها `Unknown` هنا؛ لا ادعاء توافق Laravel/PHP أو إصدار، ولا تثبيت أو dependency. يلزم فحص المصدر الرسمي، قيود Composer المستهدفة، الدعم والترخيص والأمن ومعالجة/احتفاظ البيانات، schema typed، المهلات/التكلفة والاختبارات وقابلية الاستبدال وفق [استراتيجية الحزم](../PACKAGE_STRATEGY.md). لا يُنشأ توثيق مزود جديد في هذا القرار.

## اختبارات مستقبلية قبل أي تفعيل — `NOT RUN`
| الحالة | الإثبات المطلوب |
|---|---|
| Prompt injection في مستند/رسالة تطلب تجاهل السياسة أو كشف بيانات/استدعاء tool | يعامل المحتوى كبيانات غير موثوقة؛ لا استدعاء امتيازي ولا أثر جانبي؛ finding فقط. |
| الخصوصية والنطاق | مستخدم/سجل/حقل/إسناد غير مصرح مرفوض قبل adapter؛ payload يسمح فقط بالحقول اللازمة؛ لا raw PII/secrets في payload أو logs. |
| outage وinvalid output | timeout/تعطيل/schema غير صالح ينتج `unavailable/invalid`؛ تثبت قواعد الصلاحية والمخزون والدفتر والموافقات الحتمية استمرار الرفض الصحيح دون mutation. |
| replay وidempotency | على fixtures منقحة/مصطنعة، يعاد تشغيل trace محفوظ بلا اتصال خارجي؛ تطابق hashes/versions والارتباط، ولا يتكرر finding أو أثر. لا يفترض حتمية استجابة النموذج. |
| stale subject | غيّر subject version بعد الطلب وقبل المراجعة؛ النتيجة القديمة `stale` ولا تعامل كحالية؛ يلزم تشغيل جديد ومراجعة بشرية. |
| evaluation | مجموعة مصطنعة/منقحة ذات labels ومراجعين وإصدار؛ قياس FP/FN والالتباس/الثقة والكمون والكلفة لكل فئة وإصدار؛ عتبات القبول ما زالت `TBC`. |

## قائمة قبول لاحقة — مرتبطة بـ`OPEN-09` و`OPEN-10`
- [ ] `OPEN-09`: قرار مسبب وتوقيع Executive + Security على مزود/نموذج/منطقة أو عدم الاستخدام، فئات التدقيق والمخاطر المتبقية؛ إثبات data flow وDPA/المعالجة وsubprocessors والتدريب والاحتفاظ والحذف وkill switch.
- [ ] `OPEN-09`: ميزانية وحد إنذار/إيقاف؛ مجموعة تقييم مراجعة ومنقحة، تعريفات وعتبات FP/FN والجودة والكمون والكلفة؛ نتائج الاختبارات أعلاه ومعالجة العيوب ومراجعة بشرية وصلاحيات disposition موثقة.
- [ ] `OPEN-10`: اعتماد Legal + HR/Finance للغرض والحقول والأساس/الموافقة عند انطباقها، المواقع والوصول والاحتفاظ والحذف للمدخلات والمخرجات والمراجع والنسخ؛ اختبار أن التخزين والتدقيق لا يحتفظان ببيانات أكثر من المسموح.
- [ ] بعد تحديد stack فقط: توثيق فحص توافق/صيانة/أمن/ترخيص الحزمة أو سبب عدم استخدامها واختبار adapter وخطة الاستبدال؛ لا قبول بالتخمين.

## القرار والحالة
Decision: غير معتمد. لا توقيع أو موافقة أو تاريخ اعتماد أو دليل تنفيذ مسجل. حتى استيفاء قائمة القبول واعتماد المالكين، لا إرسال خارجي ولا تفعيل ولا تثبيت حزمة؛ تبقى المهام الإنتاجية المتأثرة محجوبة. الاختبارات أعلاه مستقبلية و`NOT RUN`.
