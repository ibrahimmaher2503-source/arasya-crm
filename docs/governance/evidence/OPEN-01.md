# OPEN-01 — موجز قرار أهلية العمولات

| الحقل | القيمة |
|---|---|
| المالك وصاحب القرار | Executive + Finance |
| الحالة | OPEN — أدلة وخيارات فقط؛ لا trigger أو نسبة أو سياسة معتمدة هنا |
| نقطة الحجب | قبل حساب/تفعيل العمولة في A4 |
| المهمة | `A0-OPEN-01` |
| حدود النطاق | PAY-01..04 وKPI-04؛ هذا الموجز لا يغير قراراً آخر ولا يفعّل سلوكاً |

> كل قيمة أو معالجة غير محسومة أدناه `TBC`. لا تُفسر الأمثلة الرمزية كتوصية أو قيمة إنتاجية. تبقى `OPEN-01` مفتوحة حتى قرار موثق وتوقيع Executive وFinance.

## 1. المطلوب والثوابت

- `PAY-01`: سجّل الراتب الأساسي والعمولة والمكافأة والسلفة والخصم المعتمد كلّاً على حدة؛ الملخص الصافي لا يدمج مصادرها.
- `PAY-02`: اربط الموظف بنتيجة بيع مؤهلة ومعتمدة؛ قد تكون القاعدة عقداً أو فوترة أو تحصيلاً أو إكمالاً، ومبلغاً ثابتاً أو نسبة أو شرائح. منع التكرار وإعادة الحساب/العكس عند الإلغاء أو الرد مطلوبان، أما شروطهما فـ `TBC`.
- `PAY-03`: مراجعة Finance والتعديل/الدفع انتقالات منفصلة. لا ينفذ Finance خصماً إلا بطلب وموافقة إدارية موثقين مع الفترة والمبلغ والسبب والتدقيق؛ صاحب صلاحية اعتماد الصرف/الدفع وفصل الواجبات `TBC`.
- `PAY-04`: أي معاملة ضريبية أو تأمينات يهيئها محاسب محلي بعد تحقق قانوني حالي وتوقيع صريح؛ المعدلات والفئات والمعالجة `TBC`، ولا معدل مصري hard-coded.
- `KPI-04`: توثيق الهدف الفائت وتاريخه واستثناءاته لا يحوله إلى عقوبة راتب أو خصم تلقائي.
- سجل العمولة/الاستحقاق ليس موافقة Finance ولا إثبات دفع. تسلسل العمل المقصود للمراجعة: نتيجة معتمدة ← إسناد موظف ← أهلية وفق نسخة سياسة ← استحقاق قابل للتتبع ← مراجعة Finance ← دفع/تعديل مصرح به مع دليله. صلاحيات كل انتقال وحالاته `TBC`.

## 2. بدائل trigger — مقارنة دون اختيار

| البديل | متى يبدأ فحص الأهلية؟ | المفاضلة وما يجب تعريفه قبل الاختبار |
|---|---|---|
| توقيع العقد | عند توقيع نسخة عقد نافذة ومعتمدة، مع دليل `contract.signed` | أبكر إشارة وربط واضح بالنسخة؛ قد يسبق الفوترة/التحصيل أو الإكمال ثم يقع إلغاء/تعديل. تعريف التوقيع الصحيح والنسخة النافذة وتاريخ الأهلية `TBC`. |
| إصدار الفاتورة | عند إصدار الفاتورة أو ترحيلها — اختيار الحدث الدقيق `TBC` | يقيس قيمة مفوترة، لكن الفاتورة قد تكون مرحلية/غير محصلة أو تُصحح بإشعار دائن. حالة الفاتورة المؤهلة، الأساس، والاستثناءات `TBC`. |
| التحصيل | عند استلام وتخصيص دفعة صالحة إلى فاتورة/سطر | يربط العمولة بالنقد المحصل ويؤخرها عند تأخر العميل؛ يتطلب معالجة الدفعات الجزئية وغير المخصصة والرد/chargeback. حدث التحصيل المؤهل وقاعدة التخصيص `TBC`. |
| الإكمال | عند اكتمال عمل/تسليم/مرحلة موثقة ومقبولة | أقرب لإثبات النتيجة المنفذة؛ تعريف الإكمال والإثبات والقبول والرفض والإنجاز الجزئي `TBC`. لا يعني اعترافاً بالإيراد ولا يحسم `OPEN-05`. |

لا اختيار حالياً بين trigger واحد أو مراحل/استحقاق متعدد. عند الاختيار، يجب تحديد ترتيب الأحداث المتأخرة، النسخة/السطر المصدر، تاريخ القطع، وما إذا كان trigger لاحق يؤكد أو ينشئ جزءاً إضافياً؛ كلها `TBC`.

## 3. عناصر السياسة المطلوب حسمها

| المجال | بدائل/أسئلة قابلة للقرار | القيمة الحالية |
|---|---|---|
| أساس العمولة | إجمالي/صافي؛ قبل/بعد الخصم أو الضريبة أو الشحن؛ مستوى العقد/الفاتورة/السطر/المشروع؛ استبعاد الإشعار الدائن؟ | `TBC` لكل نوع معاملة ومصدر |
| ثابت/نسبة/شرائح | مبلغ ثابت أو `B × r` أو قاعدة شرائح؛ إن وجدت شرائح: هامشية أم بأثر رجعي، thresholds والتجميع والفترة | `TBC`؛ لا مبلغ أو نسبة افتراضية |
| دفعات جزئية | لكل تخصيص تحصيل، عند بلوغ نسبة/مبلغ، أم بعد اكتمال التحصيل؛ التعامل مع دفعة غير مخصصة أو متأخرة | `TBC`؛ لا استحقاق ضمني من callback مكرر |
| split | من يشارك (منشئ الفرصة/مغلق الصفقة/مساعد/فريق)، دليل المساهمة، الحصة والتغيير بعد handover؛ هل يسمح بباقٍ غير موزع؟ | `TBC` بما في ذلك قاعدة مجموع الحصص |
| سقوف وحدود | حد لكل صفقة/موظف/فترة، طريقة التجميع وإعادة الضبط، وما يحدث لما فوق الحد | `TBC`؛ لا حد أدنى أو أقصى مفترض |
| عملة ودقة | عملة المصدر مقابل عملة كشف الرواتب، عملات مسموحة، FX source/date/version، دقة التخزين والحساب والعرض | `TBC`؛ لا تحويل ضمني أو `float` |
| تقريب وتوزيع الباقي | موضع التقريب (سطر/دفعة/استحقاق/صرف)، `rounding_mode`، توزيع فرق التقريب بين الموظفين/الأسطر | `TBC`؛ لا منزلتين ولا `HALF_UP` مفترضة |
| الضرائب/التأمينات | هل/متى تطبق فئة مخصومة على العمولة، مرجع المحاسب، تاريخ السريان، وتغييرها | `TBC`؛ PAY-04 يمنع اختلاق معدل نظامي |

للتوضيح الرمزي فقط: `B` أساس مؤهل، `r` نسبة، `P1` و`P2` دفعتان مخصصتان، `s1/s2` حصتا موظفين، و`τ` حد شريحة. لا تحدد هذه الرموز قيمة أو طريقة: صيغة `B × r` أو احتساب كل `Pi` أو تطبيق `s1+s2` لا تنفذ إلا إذا وقعها المالكان.

### نسخة السياسة والإسناد الوظيفي

- اطلب `policy_id`, `policy_version`/hash، النطاق (كيان/نوع صفقة/فريق)، تاريخ السريان، المالكين والموافقات، وقاعدة الانتقال بين النسخ؛ كلها `TBC`. يسجل كل استحقاق النسخة والمدخلات التي حسبته. لا يعاد كتابة أثر تاريخي بصمت.
- يحدد المالكان هل التغيير يسري على المصادر الجديدة فقط أم يعيد تقييم مصادر قائمة، وكيف تعالج الاستحقاقات المعلقة؛ الأثر الرجعي وخطة إعادة الحساب `TBC`.
- يحدد القرار مصدر الحقيقة لإسناد الموظف (assignment/approved revision/مساهمة موثقة)، لحظة تثبيت الإسناد، وقواعد قبول handover وتاريخ نفاذه وتقسيم العمل قبله/بعده. حفظ سجل المالكين والإصدارات مطلوب؛ نسبة الاستحقاق قبل/بعد التسليم `TBC` ولا تتغير لمجرد تغيير المالك الحالي.

## 4. الإلغاء والرد بعد الاستحقاق أو الدفع

| التوقيت | قرار مطلوب من Executive + Finance | حد التدقيق المقترح للاختبار |
|---|---|---|
| إلغاء/رد قبل trigger المختار | ما الحدث الذي يلغي الأهلية، وهل تؤثر كمية/قيمة جزئية؟ `TBC` | لا استحقاق قبل الحدث المختار؛ لا يعتبر حدث إلغاء مكرر سبباً لأثر مكرر. |
| بعد accrual وقبل الدفع | إعادة حساب أو عكس كلي/جزئي، معالجة الفاتورة/التحصيل/السطر، وموافقات الاستثناء `TBC` | احتفظ بالأصل؛ أنشئ adjustment/reversal جديداً مرتبطاً به وبمصدر الإلغاء/الرد، مع سبب وactor/time ونسخة السياسة. |
| بعد payout | هل يوجد تصحيح مستقبلي أو مسار آخر، ومن يطلبه ويوافقه؟ `TBC` | لا حذف أو تغيير صرف سابق؛ لا استرداد أو خصم راتب تلقائي. أي خصم يتطلب طلباً وموافقة إدارية موثقين وفق `PAY-03`، ثم معالجة Finance مصرح بها. |
| رد/إلغاء جزئي أو متكرر | ترتيب الأولوية، أساس تخفيض العمولة، سقف العكس، وفترة القيد/التعديل `TBC` | ربط كل أثر بمصدره الأصلي؛ لا يتجاوز مجموع العكس الأثر القابل للعكس وفق السياسة الموقعة، ولا يطمس تاريخ الاستحقاق أو الدفع. |

إشعار الإلغاء أو الرد ليس أمراً لتغيير سجل صرف/عمولة أو قيد محاسبي مباشرة. إن لزم قيد، يقرره Finance وفق `OPEN-03`؛ لا يحسم هذا الموجز معالجة دفتر الأستاذ.

## 5. مفاتيح المصدر ومراجعة Finance والدفع

- اعتمد مفتاحاً فريداً يمنع الاستحقاق المكرر عند retry أو وصول الأحداث بترتيب مختلف. عناصر المفتاح المقترحة للنقاش: `entity_id`, نوع/معرف/نسخة المصدر، `accounting/eligibility_event_key`, سطر أو تخصيص دفعة، الموظف، ونوع الأثر/العكس. تركيب المفتاح وسياسة التصادم `TBC`؛ تخزن نسخة السياسة كمرجع ثابت، ولا ينشئ تغييرها استحقاقاً ثانياً تلقائياً.
- احتفظ بمراجع ثنائية الاتجاه: مصدر مؤهل ↔ استحقاق/تقسيم موظفين ↔ مراجعة Finance ↔ payout؛ والعكس يشير إلى الاستحقاق/الصرف الأصلي وإلى حدث refund/cancel. `reversal_key`, التسوية الجزئية، واختيار event IDs `TBC`. إعادة المفتاح بنفس payload تعيد نفس النتيجة؛ اختلاف payload لا يعدّل الأصل.
- افصل الحالات/الصلاحيات بين احتساب مستحق، مراجعة Finance، اعتماد الصرف، وإثبات تنفيذ الدفع. actor المراجع/الدافع، حدود الفصل، الفترة وطريقة إثبات الدفع `TBC`. `commission.eligible` دليل استحقاق/مراجعة وليس دفعاً.
- الخصم من الراتب منفصل عن عكس العمولة وعن دفع العمولة؛ لا خصم بسبب هدف فائت أو رد عميل تلقائياً. أي فئة ضريبية/تأمينية تنتظر رأي محاسب واعتماد PAY-04 ولا تستنتج من قيمة العمولة.

## 6. حالات رمزية وشروط الاختبار

كل fixture أدناه sanitized؛ لا مبالغ أو نسب أو عملات فعلية. شروط النجاح مرتبطة بخيارات يوقعها المالكان، وليس باختيار هذه المذكرة.

| ID / الحالة | شروط النتيجة المتوقعة |
|---|---|
| `OPEN01-T01` — ترتيب trigger | لصفقة واحدة `S`، سجّل أحداث العقد/الفاتورة/التحصيل/الإكمال بنسخها. ينشأ الاستحقاق مرة واحدة عند trigger المختار فقط؛ لا يكفي أي حدث أسبق، ولا ينشئ حدث لاحق نسخة ثانية. |
| `OPEN01-T02` — دفعات `P1`, `P2` على أساس `B` | اختبر كلا الجزأين وإعادة إرسال تخصيص أحدهما. يطابق المجموع قاعدة الدفعة الجزئية الموقعة؛ لا يكرر التخصيص ولا يتجاوز الأساس المؤهل بعد الرد/التسوية. لا تكتب قيمة expected قبل القرار. |
| `OPEN01-T03` — split `s1/s2` | نسبتَا موظفين مرتبطتان بنسخة الإسناد والدليل؛ يساوي الإجمالي قاعدة توزيع الحصص الموقعة، ويظهر أي جزء غير موزع بوضوح؛ لا تجاوز أو credit مزدوج عند إعادة الحدث. |
| `OPEN01-T04` — شريحة `τ` وسقف | اختبر `τ−ε`, `τ`, `τ+ε` وما قبل/على/بعد السقف المقرر. النتائج تطابق اختيار marginal/retroactive ونطاق السقف والفترة الموقع؛ لا threshold أو cap hard-coded. |
| `OPEN01-T05` — handover عند `h` | أرسل handover بطلب ثم قبول، وأعد حدث assignment القديم بعده. لا ينتقل الإسناد قبل وقت/شرط النفاذ المختار، يبقى تاريخ الطرفين مرئياً، وتطابق الحصص قاعدة الفترة؛ لا overwrite للقديم. |
| `OPEN01-T06` — إلغاء/رد | جرّب قبل trigger، وبعد accrual وقبل payout، وبعد payout، ورداً جزئياً ومكرراً. الأثر لكل حالة يطابق السياسة الموقعة، مرتبط بالأصل والمصدر، ولا يعدل الأصل؛ لا خصم راتب تلقائي. |
| `OPEN01-T07` — dedupe/reversal | تزامن/replay للمصدر نفسه ينتج استحقاقاً واحداً؛ payload مختلف للمفتاح نفسه يُرفض دون mutation. reversal واحد لكل طلب/مفتاح، مربوط بالأصل، وإعادة المحاولة تعيد نفس النتيجة. |
| `OPEN01-T08` — العملة والتقريب | عملة غير مغطاة أو FX/rounding policy غائبة تُحجب بأسباب واضحة؛ decimal دقيق بلا float. بعد التوقيع تطابق حدود التقريب وتوزيع الباقي fixture المعتمد ونسخة السياسة، بلا فرق غير مفسر. |
| `OPEN01-T09` — المراجعة والصرف | accrual أو مراجعة Finance وحدها لا تسجل paid؛ الدفع لا يظهر إلا عبر انتقال مصرح ودليل تنفيذ. خصم بلا طلب وموافقة إدارية موثقين يُرفض مع عدم mutation وأثر تدقيق. |
| `OPEN01-T10` — هدف فائت | تبقى لقطة الهدف/التقييم والتنبيه قابلة للتتبع، ولا ينشأ خصم/تغيير payroll لمجرد miss؛ محاولة خصم آلي بلا طلب وموافقة موثقين مرفوضة. |

اجعل `AT-08` قبولاً end-to-end: accrual مرة واحدة، cancel ينتج reversal/adjustment وفق policy، وكشف الموظف يصل للمصدر. افحص DB/outbox/audit والكشف، replay والتزامن وحالة الرفض دون mutation، باستخدام fixtures sanitized ونتائج مالية لا تعتمد إلا بعد توقيع المالكين.

## 7. أسئلة المالك وطلب البيانات

على Executive + Finance حسم trigger وترتيبه وأساس المبلغ، قواعد الدفعات الجزئية، fixed/percentage/tiers/splits/caps، الإسناد وhandover، currency/rounding، وrefund/cancel قبل/بعد payout ومفتاح المصدر. يطلب رأي محاسب محلي لـ PAY-04؛ وتقدم Sales/Operations/Delivery عينات حالة الإكمال والإسناد دون أن تصبح مالكة القرار التجاري.

| البيانات المطلوبة من Finance/Sales/Operations | مدخل المالك / المرجع المنقح |
|---|---|
| أمثلة contract/invoice/collection/completion متقابلة، مع status وrevision وأوقات الحدث | `TBC` — معرفات مصطنعة أو منقحة؛ لا بيانات شخصية غير لازمة |
| فاتورة مع تخصيصات `P1/P2`، دفعة غير مخصصة، وrefund/credit/cancel | `TBC` — مراجع مستندات وتوقيتاتها والنتيجة الحالية |
