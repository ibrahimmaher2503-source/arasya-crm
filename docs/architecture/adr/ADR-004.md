# ADR-004 — تخزين الملفات الخاصة

Status: OPEN
Owner: IT + Security
آخر فحص للمصادر: `2026-10-15T20:53:13+03:00`؛ لا يمثل اعتماداً.
النطاق: مقارنة قرص Laravel محلي خاص بتخزين كائنات خاص متوافق مع S3؛ لا اختيار لمزود أو بيئة إنتاج.

## السياق والقيود المؤكدة
- Laravel مؤكد، والتفضيل الهندسي package-first مؤكد؛ النسخة والحزم ومزود التخزين غير محددة.
- `DOC-01/02` تتطلب مستودع وثائق غير عام، رفعاً وتنزيلاً آمنين، تحقق MIME وبرمجيات خبيثة، إصدارات، checksum، تدقيقاً ومنع روابط التخزين العامة.
- التفويض deny-by-default على مستوى السجل والحقل والكيان، ويشمل التنزيل والتصدير والوظائف؛ لا يكفي إخفاء الواجهة.
- يرتبط ذلك بـ`NFR-01` للخصوصية والتفويض، و`NFR-03` للاستعادة، و`NFR-08` للاحتفاظ؛ و`ARCH-03` يطلب provider abstraction دون اختيار مزود.
- سجل `Attachment` و`DocumentVersion` مقترح؛ بيانات الملف لا تصبح متاحة قبل التحقق والتثبيت.
- `OPEN-10`: الاحتفاظ، الوصول القانوني وlegal hold غير محسومة. `OPEN-11`: الاستضافة، المنطقة، الحمل، التوافر وRPO/RTO غير محسومة.

## الدليل الرسمي وحدوده
- توثيق [Laravel Filesystem 12.x](https://laravel.com/docs/12.x/filesystem) يصف Laravel Filesystem فوق Flysystem، وقرص `local` خاصاً افتراضياً تحت `storage/app/private`، وقرص S3 مع إمكان ضبط endpoint لخدمات S3-compatible.
- يوثق `temporaryUrl` و`temporaryUploadUrl` لبعض أقراص `local` و`S3`. هذا دليل على واجهة Laravel فقط؛ لا يثبت إعداداً آمناً، أو دعماً متكافئاً للخصائص لدى أي خدمة، أو توافق نسخة المشروع التي لم تُحدد.
- راجعت [استراتيجية الحزم](../PACKAGE_STRATEGY.md): `spatie/laravel-medialibrary` مرشح لربط الوسائط والمجموعات والتحويلات، لا حل أمني شامل ولا اعتماداً للحزمة.

## البدائل والمقايضات
| البديل | ما قد يتيحه | متطلبات/مخاطر يجب إثباتها |
|---|---|---|
| قرص `local` خاص عبر Laravel/Flysystem | أقل مكونات خارجية؛ تحكم مباشر بملفات الخادم؛ إعداد محلي أبسط. | جذر خارج web root، صلاحيات OS/service account، تشفير ومفاتيح، سعة ومراقبة، عزل/مشاركة عند تعدد العقد، تحمل تعطل القرص، نسخ واستعادة واختبارها؛ الاعتمادية والتوسع مسؤولية التشغيل. |
| مخزن كائنات خاص متوافق مع S3 عبر Laravel/Flysystem | فصل بيانات الملفات عن عقد التطبيق؛ قد يدعم رفعاً مباشراً ونسخاً وإصدارات وضوابط تشغيلية. | تحقق فعلي من منع public access، IAM أقل صلاحية، TLS والتشفير واستعادة المفاتيح، versioning/checksum/logging، URLs المؤقتة والرفع المجزأ، النسخ والحذف والتصدير؛ توافق S3 لا يضمن تطابق السلوك. تبقى الشبكة، الأعطال، الإقليم، التعاقد والخروج مسؤوليات يجب تقييمها. |

لا توجد معلومات موثقة تحسم المفاضلة في المرونة أو الاستعادة أو الكلفة؛ لا مزود أو region أو SLO أو سعر أو حجم/مدة افتراضية مختارة.

## نهج الحزم
- ابدأ بتقييم واجهة Laravel Filesystem/Flysystem وعقدها القابلة للاختبار قبل custom storage plumbing. تحقق من إصدار Laravel/PHP والـadapter والـComposer constraints عند تحديدها؛ لا تثبّت حزمة بهذا السجل.
- توثيق Laravel يذكر adapter منفصلاً لـS3؛ إثبات توافق الخدمة، خصائصها واختبارات التكامل مطلوب لكل مرشح. لا تفترض أن abstraction تنفذ المسح أو التفويض أو النسخ.
- `Spatie Media Library` يبقى Candidate: لا يفرض الصلاحية حسب السجل/الكيان، ولا يضمن quarantine أو MIME signature أو malware scan أو checksum أو سياسة retention أو استعادة متسقة.

## عقد الرفع والتنزيل المقترح للتقييم
1. بدء الرفع: تحقق الخادم من هوية actor وصلاحيته للـrecord والـentity ونوع الوثيقة؛ أنشئ upload intent محدوداً وحالة `quarantined` ومفتاحاً عشوائياً من الخادم. لا تستخدم مساراً أو اسماً يحدده العميل. أي URL مباشر مؤقت يقتصر على كائن quarantine، ويعامل كـbearer secret.
2. ارفع إلى مساحة خاصة ومعزولة عن ملفات `ready` وعن web root؛ قيّد الحجم والنوع وفق سياسة يحددها المالك. تعامل مع المحتوى كغير موثوق ولا تعرضه أو تحوله قبل الفحص.
3. تحقق من الحجم وMIME الفعلي وتوقيع الملف/magic bytes، لا ترويسة العميل أو الامتداد وحدهما؛ افحص البرمجيات الخبيثة، واحسب checksum من البايتات المستلمة. فشل الفحص أو تعذره يمنع الإنهاء.
4. الإنهاء idempotent: أعد التحقق من ملكية intent وحالته ونتائج الفحص وchecksum، ثم ثبّت بايتات سليمة بمفتاح نهائي فريد غير قابل لإعادة الاستخدام، وسجل `DocumentVersion` ونتيجة التدقيق. لا تفترض ذرية معاملة DB والملف؛ عالج الانقطاع وإعادة المحاولة بحالات صريحة.
5. احتفظ بإصدارات التطبيق ككائنات غير قابلة للكتابة فوقها؛ التخزين الأصلي للإصدارات في خدمة S3، إن توفر، ميزة إضافية لا بديل عن سجل النسخ والتحقق.
6. التنزيل لا يبدأ إلا بعد تفويض خادمي جديد للـactor والسجل والـentity والنسخة الحالية؛ سجّل الحدث دون تسريب المحتوى. أعد التفويض كذلك عند تشغيل export وعند تنزيل ناتجه، وطبّق field masking.
7. الرابط الموقّع bearer قابل للنسخ/التمرير؛ قصر عمره يقلل نافذة التعرض ولا يسحب رابطاً صدر بالفعل فوراً. الإلغاء يمنع إصدار روابط جديدة، أما الرابط القائم فقد يبقى صالحاً حتى انتهاء صلاحيته أو إبطال قدرة المزود؛ استخدم proxy خادمياً عند الحاجة إلى إعادة تفويض فورية. لا توجد مدة معتمدة.
8. المسارات مفاتيح يولدها الخادم ولا تُركب من اسم العميل أو مسار نسبي. نظّف الاسم الأصلي للعرض و`Content-Disposition` فقط؛ ارفض traversal والفواصل/الترميزات الملتبسة وsymlinks. طبّق الحماية نفسها على ملفات وentries التصدير المؤقتة.

## النسخ والاستعادة واليتامى
- لا توجد معاملة ذرية مشتركة بين DB ومخزن الملفات. نسّق نقطة النسخ/manifest لتشمل سجل الوثائق والإصدارات ومفاتيح الكائنات وchecksums ومفاتيح/وسيلة فك التشفير، مع إبقاء بيانات `pending` غير مرئية كمستند مكتمل.
- تمرين الاستعادة يجب أن يعيد DB والملفات من نقطة متوافقة، ويفحص المراجع وعدد الملفات وchecksum والتفويض وسجلات audit؛ لا يكفي نجاح إنشاء backup. `OPEN-11` لا يملك أهداف RPO/RTO أو تمريناً معتمداً.
- reconciliation يرصد سجل بلا كائن، وكائناً بلا سجل، وchecksum/version مفقوداً، ورفع quarantine عالقاً. لا يحذف يتيمة تلقائياً قبل سياسة retention/legal hold معتمدة؛ طبّق tombstones المعتمدة كي لا يعيد restore بيانات محذوفة.

## اختبارات مرشحة قبل القبول — `NOT RUN`
- scope/IDOR ورفض كيان أو مستخدم غير مخول، وسحب الصلاحية بين بدء الرفع والتنزيل أو إنشاء/تنفيذ/تنزيل export.
- MIME وتوقيع متعارضان، polyglot، حجم زائد، ملف فحص آمن، تعطل scanner، checksum خاطئ، انقطاع/retry/finalize متكرر، وتزامن الإصدارات.
- `../` والترميز والفواصل وأسماء Unicode وsymlinks ومسارات ZIP/export؛ لا قراءة أو كتابة خارج الجذر.
- صلاحية/تمرير/انتهاء signed URL وحدود الإلغاء، مع سلوك كل adapter فعلي.
- backup/restore متوافق DB+files ومفاتيح، كشف missing/orphan/hash mismatch، وإعادة reconciliation دون حذف غير مصرح.
- اختبارات توافق محلية وتكامل مع S3-compatible مرشح على الخصوصية والفشل والاستعادة؛ لا خدمة محددة حالياً.

## الأدلة المطلوبة والأسئلة المفتوحة
- يثبت IT/Security الإعداد الخاص والتشفير وإدارة المفاتيح والصلاحيات وسجل الوصول، ومسح الملفات ومسار الرفع والتنزيل والتصدير واختبار استعادة فعلياً.
- يحدد المالك: تصنيف الوثائق ومنحها، حدود الأحجام/الأنواع، scanner، وسياسة versioning والاحتفاظ والمحو وlegal hold ومواقع المعالجة.
- يحدد IT/Engineering: الحمل والتوافر وRPO/RTO، مسؤولية التشغيل، متطلبات نقل/تصدير البيانات، المرشح/الـadapter، وتكلفة مدعومة بعرض؛ لا قيَم مثبتة هنا.
- تبقى `OPEN-10/11` مفتوحة. لا قبول أو sign-off أو اعتماد إنتاجي مسجل؛ لا تتغير حالة المهام أو السياسة بهذا التقييم.

## النتيجة الحالية
لا يُختار القرص المحلي أو مخزن S3-compatible في هذا السجل. يظل `Status: OPEN` إلى أن تُستكمل الأدلة ويعتمد IT/Security والمالكون المختصون القرار؛ تبقى مهام التنفيذ المتأثرة محجوبة، ولا تعني المواصفات أو spikes موافقة إنتاجية.
