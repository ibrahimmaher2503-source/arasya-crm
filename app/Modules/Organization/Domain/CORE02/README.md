# CORE02 stable identity and linkage

This slice provides a typed, immutable read projection over an explicitly supplied identity catalog. `RecordKind` is the closed set from PRD CORE-02: customer, lead, employee, project, contract, quotation, stock item, invoice, expense, and document. `RecordIdentity` accepts only bounded ASCII identifier tokens (1–128 characters) for both record and entity IDs; arbitrary display/free text is not an identity.

`RecordLinkageGuard::project` succeeds only when the projected identity and every linked identity exist exactly in the supplied catalog, all links have the same entity ID as the projected record, and the catalog contains no repeated `(entity, id)` even if a repeated ID claims another kind. Malformed catalog entries, unresolved/wrong-kind/cross-entity links, and oversized snapshots fail closed with `null`. The returned readonly model and typed identity/link values do not mutate caller-owned input; replaying the same inputs yields the same projection.

Policy reference: [PRD CORE-02](../../../../../docs/product/PRD.md#core-02--unified-identity-and-record-linkage) requires stable unique IDs and record links rather than duplicated free text. No OPEN decision or financial/business policy is introduced. This is a local read-only fixture projection: persistence, durable/system-wide uniqueness, mutation audit/outbox, and authorization are N/A. The supplied catalog proves only consistency within that snapshot; it is not a database constraint, global registry, real auth boundary, or cross-module write contract. Assistant coverage is N/A because this is a restricted/disabled local read-only fixture projection with no real registry and no assistant capability.
