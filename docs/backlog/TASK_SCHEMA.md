# مخطط المهام
Root: schema_version وplanning_only وtasks. كل task ثابتة الحقول: id/title/increment/epic/objective/prd_refs/depends_on/blocks/decision_dependencies/scope/deliverables/acceptance_criteria/verification/parallel_group/status/size/agent_notes.

id فريد `A0-SEC-001`، increment A0..A5، epic رمز domain. prd_refs قائمة IDs أصلية. depends_on predecessors، blocks العكس المحسوب تماماً. decision_dependencies قائمة OPEN أو ADR غير معتمد؛ لا يشترط أن تكون task IDs. لا يثبت Approved/Accepted status وحده: يلزم سجل `docs/governance/decision-approvals/<ref>.md` بكل حقول المالك والتاريخ والخيار والدليل والمهام والفحوص والمراجعة، ودليل منفصل موجود؛ OPEN status = Approved، وADR status = Accepted في index والملف. الأداة تتحقق فقط ولا تنشئ اعتماداً. scope.paths وscope.modules تحفظ ownership المتوقع لا وجود ملفات التطبيق الآن. deliverables وacceptance_criteria وverification قوائم غير فارغة؛ verification خطوات/أوامر مستقبلية لا نتائج.

status: blocked إذا قرار غير محسوم مباشر؛ planned إذا ينتظر predecessors؛ ready إذا كل predecessors done وكل decision_dependencies معها سجل اعتماد صريح ودليل موجود؛ ثم in_progress/review/done حسب دليل التنفيذ. إعادة الحساب لا تغيّر status المحفوظ تلقائياً، و`blocked` يتطلب release صريح بعد المراجعة. descendants لقرار blocked قد تبقى planned لكنها لا تصبح ready. size XS أو S فقط؛ parallel_group null أو اسم candidate lane لا يتجاوز locks.

كل task جلسة واحدة. pattern: specification ثم slice implementation ثم adversarial tests حيث مناسب. لا تنفذ specification لتقرير سياسة OPEN نيابة عن المالك؛ تستطيع جمع الأدلة والبدائل. إذا feature مثل ledger أو mailbox أكبر من جلسة، split قبل التنفيذ إلى commands/queries/UI وupdate DAG والتتبع؛ لا تضع done على parent حتى الأدلة لجميع children. أقل حجم مفيد لا يعني مهمة فارغة أو module كامل. acceptance task تنتج تقرير فحص فعلي ولا تطلب تنفيذ increment كاملاً.
