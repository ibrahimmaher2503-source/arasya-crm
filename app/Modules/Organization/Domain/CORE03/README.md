# CORE03 transition guard slice

This domain-only proposal implements the invariant in [PRD CORE-03](../../../../../docs/product/PRD.md#core-03--workflow-state-machine): status changes are represented as explicit transitions, retain prior history, and do not mutate the supplied source on denial. `WorkflowState` is immutable and entity-scoped; accepted proposals increment its version and append immutable history with normalized UTC time. `WorkflowState` validates an immutable history suffix: each entry must match entity/subject scope, statuses must chain to the current status, request IDs are unique, source versions are nonnegative and contiguous, and the suffix ends at `state.version - 1`. Earlier history may be omitted as a suffix; a complete history from version zero is not required. `TransitionProposal::auditOutboxIntent` carries the same event-shaped intent for accepted changes; it is not persisted or delivered. The guard takes expected version, entity, explicit permission inputs, validator outcome, actor/correlation/request IDs, and timestamp. A replay must match the original entity, subject, target, actor, correlation ID, and source version recorded with the immutable history entry, and must still supply the edge permission and a passing validator outcome. A valid replay returns the unchanged current snapshot with no new audit/outbox intent; mismatches are denied.

`TransitionPolicy` is only an explicitly supplied synthetic fixture edge map. This code does not choose consequential status rules, authorization, validators, cancellation/reversal behavior, money thresholds, or approval hierarchy, and malformed/missing edges fail closed. It is a pure in-memory proposal, not production enforcement: no persistence, transaction/locking, durable audit/outbox, authentication/authorization, clock, or cross-module writes are provided. No schema or migration is introduced. Assistant coverage is N/A: this restricted/disabled fixture API has no assistant invocation or production decision authority.
